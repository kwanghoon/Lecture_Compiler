정규화(Canonical Trees): Canon.java

- ESEQ/SEQ 제거: 
   do_stm()/do_exp() 재작성으로 ESEQ를 끌어올리고 
   seq()로 합성하여 최종 linearize()가 
   Tree.StmList로 선형화합니다.

- CALL 최상위 제약: 
   MoveCall/ExpCall로 모든 CALL이 MOVE(TEMP, ...) 
   또는 EXP(...)의 자식이 되도록 강제합니다. 
   reorder()는 중첩된 CALL을 
   ESEQ(MOVE(TEMP t, CALL), TEMP t)로 감싸 부작용 순서를 
   안전화합니다.

- 교환 규칙: 
   commute()가 NAME/CONST만 안전 교환으로 보고, 
   나머지는 임시(TEMP)를 통해 순서를 고정합니다.

기본 블록(Basic Blocks): BasicBlocks.java + StmListList.java

 - 형식 보장: 
    각 블록의 첫 문장은 LABEL, 마지막 문장은 JUMP 또는 CJUMP. 
    중간에 LABEL이 나타나면 현재 블록을 JUMP로 닫고 새 블록 시작.

 - 알고리즘: 
    시퀀스를 스캔해 LABEL에서 블록 시작, JUMP/CJUMP에서 
    블록 종료·다음 블록으로 진행.

 - 종료 라벨: 
    입력이 점프 없이 끝나면 done 라벨로의 JUMP를 추가해 
    종결을 명시합니다.

트레이스(Traces): TraceSchedule.java

 - 블록 연결: 
     라벨→블록 테이블로 미표시 블록에서 시작해 
     trace()가 점프 체인을 따라 블록을 붙이며 하나의 긴 트레이스를 
     구성합니다.

 - CJUMP 폴스루: 
     거짓 레이블 블록이 있으면 바로 뒤에 배치. 
     참만 있을 경우 CJUMP.notRel로 조건을 반전해 폴스루가 
     거짓이 되도록 조정. 둘 다 없으면 새 거짓 라벨을 만들어 
     LABEL(ff)와 JUMP(iffalse)를 삽입해 불변식을 만족시킵니다.

 - 평탄화/최적화: 
     트레이스들을 하나의 StmList로 평탄화하고 인접한 JUMP와 
    대상 LABEL의 중복을 줄입니다.

Canon (linearize) 구현 

abstract public class Exp {
  abstract public ExpList kids();
  abstract public Exp build(ExpList kids);
}

Step one is to make a “subexpression-extraction” method for
each kind. Step two is to make a “subexpression-insertion” method: Given
an ESEQ-clean version of each subexpression, this builds a new version of the
expression or statement.

Using these build methods, we can write functions

  static Tree.Stm do_stm(Tree.Stm s)
  static Tree.ESEQ do_exp (Tree.Exp e)

that pull all the ESEQs out of a statement or expression, respectively. That
is, do_stm uses s.kids() to get the immediate subexpressions of s, which
will be an expression-list l. It then pulls all the ESEQs out of l recursively,
yielding a clump of side-effecting statements s1 and a cleaned-up list l'. Then
SEQ(s1, s.build(l')) constructs a new statement, like the original s but with
no ESEQs.

These functions rely on auxiliary functions reorder_stm and
reorder_exp for help.

  static Tree.Stm reorder_stm(Tree.Stm s)
  static Tree.ESEQ reorder_exp (Tree.Exp e)

Highlights

 - 목적: Tree.Stm을 Tree.StmList로 평탄화하고 ESEQ/중첩 CALL 제거.
 - 핵심 규칙: 좌→우 인자 재배치, 교환 불가 시 TEMP로 임시 저장, SEQ/ESEQ 제거, CALL 승격(MoveCall/ExpCall).
 - 순서 보장: 원래 평가 순서·부작용 보존, 교환 가능성(NAME/CONST 또는 NOP)만 재배치.
 - 결과 형태: 각 문장 자식은 순수 표현식, 리스트에는 가능하면 EXP(CONST)가 남지 않음.
 - 예시 포함: MOVE(ESEQ(...), ...)와 EXP(CALL ...) 정규화 후 선형화 흐름.


 Basic Block으로 쪼개기의 핵심 요점

 - 모든 블록은 LABEL로 시작하며, 없으면 새 라벨을 삽입한다.
 - 블록은 JUMP 또는 CJUMP로 종료되며, 리스트가 다른 문장으로 끝나면 JUMP(done)을 덧붙인다.
 - 블록 중간에 LABEL이 나타나면 해당 라벨로의 JUMP를 추가해 현재 블록을 종료하고, 그 라벨에서 새 블록을 시작한다.
 - done은 마지막에 삽입되는 점프의 목적지로 쓰이는 종착 라벨이며, 이후 스케줄링/플로우 단계에서 소비된다.
