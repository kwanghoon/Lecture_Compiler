* Instruction Selection

선호하는 명령어 집합은 Mips이다. 
 Maximal Munch를 사용하여 Assem-명령어로의 변환을 구현하시오. 
 James Larus가 구현한 MIPS 시뮬레이터 SPIM을 사용하여 테스트할 수 있다.
 
 먼저 IR 트리에서 Assem 데이터 구조로의 Maximal Munch 변환 알고리즘을 
 구현하는 클래스 .Codegen을 작성하시오. Codegen 모듈을 적용하기 전에 
 Canon 모듈을 사용하여 트리를 단순화하시오. 
 그 결과 Assem 트리를 어셈블리 언어로 변환하기 위해 format 함수를 사용하시오. 
 
 아직 레지스터 할당을 하지 않았으므로, 임시변수에서 문자열로의 변환 함수로 
 format에 new Temp.DefaultMap()을 그대로 전달하시오.

    package Temp;

    public class DefaultMap implements TempMap {

        public String tempMap(Temp.Temp t)
                { return t.toString(); }
    }

이렇게 하면 레지스터 이름을 전혀 사용하지 않는 어셈블리 언어가 생성됩니다. 
명령어들은 t3, t283 등의 이름을 사용하는데, 이들 중 일부 임시변수는 
Frame 모듈이 특정 머신 레지스터(143페이지 참조)를 나타내기 위해 만든 
"내장" 임시변수입니다(예: Frame.FP). 프레임 모듈은 특수 임시변수를 
그들의 자연스러운 이름으로 표시(fp가 t1 대신 나타나도록)하면 
어셈블리 언어를 더 읽기 쉽게 만들 수 있습니다. 프레임 모듈은 특수 임시변수에서 
이름으로, 특수하지 않은 임시변수에서는 null로 매핑을 제공해야 합니다:

    package Frame;

    public class Frame implements Temp.TempMap {
        :
        :
        : abstract public String tempMap(Temp temp); }

그런 다음, 레지스터 할당 이전에 어셈블리 언어를 표시하기 위한 목적을 위해, 
먼저 frame.tempMap을 시도하고 그 결과가 null이면 Temp.toString()으로 
대체하는 새로운 TempMap 함수를 만드시오.

레지스터 목록

다음과 같은 레지스터 목록들을 만드세요. 각 레지스터에 대해 어셈블리 언어 
표현을 위한 문자열과 Tree 및 Assem 자료 구조에서 참조하기 위한 
Temp.Temp가 필요합니다.

- specialregs RV와 FP와 같은 "특수" 레지스터, 스택 포인터 SP, 
  복귀 주소 레지스터 RA, 그리고 (일부 기계에서) 제로 레지스터 ZERO와 
  같은 것들을 구현하는 데 사용되는 $\mu$ 레지스터 목록입니다. 
  일부 기계에는 다른 특수 레지스터가 있을 수 있습니다.

- argregs 외부로 전달되는 인자(정적 링크 포함)를 전달하는 $\mu$ 레지스터 
  목록입니다.

- calleesaves 호출된 프로시저(수행자)가 변경되지 않도록 보존해야 하는
  (또는 저장 및 복원해야 하는) $\mu$ 레지스터 목록입니다.

- callersaves 수행자가 내용을 버릴 수 있는 $\mu$ 레지스터 목록입니다.

이 네 가지 레지스터 목록은 겹치지 않아야 하며, Assem 명령어에 나타날 수 
있는 모든 레지스터를 포함해야 합니다. 이 목록들은 공개적이지 않지만, 
Frame과 Codegen 모두에서 내부적으로 유용하며—예를 들어, 
munchArgs를 구현하고 calldefs 목록을 구성하는 데 사용됩니다.

    package Frame;

    class Frame implements Temp.TempMap {
        . . .
        abstract public Assem.InstrList procEntryExit2(
            Assem.InstrList body);
    }
    이 함수는 레지스터 할당기에게 특정 레지스터들이 프로시저 종료 시점에 
    여전히 유효(live)하다는 것을 알려주기 위해 함수 본문(body)에 
    "싱크(sink)" 명령어를 추가합니다. Jouette 기계의 경우, 
    이는 간단하게 다음과 같습니다:

      Java
      package Jouette;

      class Frame extends Frame.Frame {
          . . .
          static TempList returnSink = 
              L(ZERO, L(RA, L(SP, calleeSaves)));

          static Assem.InstrList append (Assem.InstrList a, 
                                         Assem.InstrList b) {
              if ( a== null) return b;
              else {Assem.InstrList p;
                    for( p=a; p.tail!=null; p=p.tail) {} 
                    p.tail =b; 
                    return a;
              }
          }

          public Assem.InstrList procEntryExit2(
              Assem.InstrList body) {
              return append (body,
                new Assem.InstrList(
                    new Assem.OPER("", null, returnSink),null));
          }
      }
      
이는 임시 레지스터인 zero, return-address, 스택 포인터, 그리고 
모든 callee-saves 레지스터들이 함수 종료 시점에도 여전히 유효하다는 
것을 의미합니다. 

zero가 끝까지 유효하다는 것은 레지스터 할당기가 다른 용도로 사용하려고 
시도하는 것을 방지하여, 이 레지스터가 전체적으로 유효함을 의미합니다. 
이와 같은 트릭은 기계가 가질 수 있는 다른 특수 레지스터에도 적용됩니다.

**C-like 매핑 (ComputeFac)**
    - 선언/초기화 `int num_aux;` → 10
    - 조건 `if (num < 1)` → 11–12
    - then 분기 `num_aux = 1;` → 25 (후속 합류로 26→13–14 진행)
    - else 분기 `num_aux = num * ComputeFac(num - 1);` → 15–22
    - 반환 `return num_aux;` → 공통 반환 준비 23, 함수 종료 점프 24
        - base case 반환 경로: 27–28로 `t3 = 1` 설정 후 23–24로 종료
        - else 경로 반환: 22에서 `t3 = num * rec`, 23–24로 종료

**C-like 매핑 (main)**
    - 객체 생성(새 Fac 인스턴스; C-like에선 무시 가능) → 1–4
    - 호출 `int t = ComputeFac(10);` → 5 (상수 10), 6 (호출), 7 (결과 수신), 8 (`t`로 이동)
    - 출력 `print(t);` → 9
